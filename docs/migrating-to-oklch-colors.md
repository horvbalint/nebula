# Migrating to the OKLCH colour scale

The colour-scale generator was rewritten. It used to build each `50…950` shade
by mixing the seed toward white/black in sRGB (`theme-colors`); it now places
every step at a target **OKLCH lightness** with WCAG contrast floors on the steps
that carry text or solid fills.

Why it changed: the old ramp had uneven lightness steps, chroma that collapsed at
the dark end (muddy dark-mode buttons), and wildly different quality per hue.
The new ramp is perceptually even, holds chroma, and behaves the same for any
brand colour.

**Nothing in the public API changed** — every generated variable
(`--primary-color-600`, `--neutral-color-component-800`, …) still exists with the
same name. Only the *values* differ, plus a few semantic-token remappings and two
default seeds. This guide is about getting back to the old look where you want it.

---

## Which path applies to you

| Your app… | Do this |
| --- | --- |
| only uses `--neb-*` semantic tokens, default brand colours | Nothing required. Expect a modest visual shift (§1). |
| only uses `--neb-*` tokens, **custom** `errorColor` / `warningColor` | Nothing — your explicit seeds still win. Default-seed apps see new hues (§2a). |
| reads raw `--{family}-color-{N}` steps in your own CSS | Audit those spots — the dark half of every ramp moved (§1, §3). |
| must not change at all this release | Pin the layer version, or freeze the palette (§4). |

---

## 1. Upgrade and review (the normal path)

### What shifts visually

- **Dark-mode solid buttons/badges** get noticeably more vivid and lighter — this
  is the main fix. `--primary-color-700` (the dark `-solid` fill) went from
  `#4A2E83` to `#6C4DB4` for the default purple.
- **Light-mode solid buttons** are now `--{intent}-color-600` instead of the raw
  seed, and hover is `-700` (a clear darken). The resting button is very close to
  your brand colour but not the exact hex — see §3b to pin it.
- **De-emphasised text is now one token.** `--neb-text-muted` was renamed to
  `--neb-text-subtle` (value unchanged: `neutral-600` light / `neutral-400` dark),
  and the old faint `--neb-text-subtle` tier (`neutral-400`/`-500`) was dropped —
  its callers (captions, placeholders, separators) now sit on the `-600` value and
  gain contrast. See §2c to restore a faint tier.
- **Neutral surfaces and text barely move** — the neutral ramp is within ~2 sRGB
  levels of the old one at most steps.
- Ramps are smoother: no more tiny 500→600 step followed by a 600→700 cliff.

### Find your risk areas

```bash
# raw scale steps in your own styles — these will look different, esp. 600–950
grep -rn "var(--\(primary\|secondary\|success\|error\|warning\|info\|neutral\)-color-[0-9]" app/ components/ assets/

# --{family}-color-500 used as "the brand colour" — 500 is no longer the seed (§3d)
grep -rn "color-500)" app/ components/ assets/

# hardcoded hexes copied from the old ramp
grep -rn "#4A2E83\|#7045C5\|#F04438\|#F79009" app/ components/ assets/
```

## 2. Keep specific things looking the same

Put any of these overrides in a non-scoped `:root {}` / `.dark-mode {}` block in
`app.vue`'s `<style>`, or an app stylesheet. Semantic tokens have single-class
specificity, so this wins by source order — if an override doesn't take effect,
it's loading before `assets/semantic.css`; move it later or apply it from a
plugin as in §4B.

### 2a. Keep the old default error / warning hues

The shipped defaults changed so they pass contrast as-is:

| seed | old | new |
| --- | --- | --- |
| `errorColor` | `#F04438` | `#D92D20` |
| `warningColor` | `#F79009` | `#A96000` |

If you never set these and want the old look, set them explicitly in
`nuxt.config.ts`:

```ts
export default defineNuxtConfig({
  nebula: {
    primaryColor: '#7c4ddb',
    errorColor: '#F04438',
    warningColor: '#F79009',
  },
})
```

Note: the *ramp* around those seeds is still generated by the new algorithm, so
mid/dark steps differ even with the same seed. `#F79009` will also emit a
build-time `[nebula]` warning that it makes a faint `--neb-border-warning-alert`
stripe — harmless, or silence it by moving to a darker amber.

### 2b. Keep the primary button as your exact brand hex

The light-mode solid fills are now step 600. To restore "solid = the configured
colour":

```css
:root {
  --neb-bg-primary-solid: var(--primary-color);
  --neb-bg-primary-solid-hover: var(--primary-color-600);
  --neb-bg-neutral-solid: var(--neutral-color);
  --neb-bg-neutral-solid-hover: var(--neutral-color-600);
  /* + success / error / warning / info, same pattern, if you use their solids */
}
```

Trade-off you're taking back on: with a light or mid-lightness brand seed the
hover barely changes, and white text on a pale seed can drop below AA. That's
exactly why the default moved to 600.

### 2c. Restore the old two-tier de-emphasised text

The layer now ships a single de-emphasised tier, `--neb-text-subtle`
(`neutral-600` / `neutral-400`). If your app relied on the old split — a `-600`
tier for secondary copy and a fainter `-400` tier for captions/placeholders —
add your own token for the faint one and point the affected rules at it:

```css
:root {
  --app-text-faint: var(--neutral-color-400);
}
.dark-mode {
  --app-text-faint: var(--neutral-color-500);
}
```

Overriding `--neb-text-subtle` itself to `-400` is **not** equivalent — it would
drag all secondary body copy below a comfortable contrast, which is why the tiers
were merged upward rather than downward.

### 2d. `--{family}-color-500` was your brand colour

The old generator made step 500 byte-identical to the seed. The new one anchors
500 to a lightness target, so it no longer equals the seed. The seed now lives
**only** in the bare token:

```css
/* before */
color: var(--primary-color-500);
/* after */
color: var(--primary-color);
```

## 3. New options

Two optional keys on the `nebula` config control the derived neutral ramp (which
is otherwise desaturated from your primary):

```ts
export default defineNuxtConfig({
  nebula: {
    primaryColor: '#2563eb',
    neutralTint: 0.008, // absolute OKLCH chroma of the greys; 0 = pure neutral
    neutralHue: 40, // degrees; defaults to the primary's hue. Warm greys under a cool brand.
  },
})
```

## 4. Change nothing this release

### Option A — pin the version

Keep the current Nebula version in `package.json` and upgrade deliberately later.
Simplest, zero risk.

### Option B — freeze the palette

Vendor the exact old variables and re-apply them as inline styles on
`<html>`, which beats every stylesheet regardless of load order (this is how
`setNebColorPalette()` already works).

1. On the **old** version, start the dev server and capture the two generated
   files while it runs — they're written at startup and deleted on shutdown:

   ```bash
   # in the old checkout, with `pnpm dev` running, from another terminal:
   cat node_modules/nebula/modules/runtime/stylesheets/colors.css \
       node_modules/nebula/modules/runtime/stylesheets/colorComponents.css
   ```

2. Turn every `--name: value;` line into a `[name, value]` pair and apply them in
   an app plugin:

   ```ts
   // app/plugins/frozen-palette.client.ts
   const FROZEN: Record<string, string> = {
     '--primary-color': '#7C4DDB',
     '--primary-color-50': '#F8F6FD',
     // …all 168 lines from step 1…
     '--neutral-color-component-950': '24, 22, 23',
   }
   export default defineNuxtPlugin(() => {
     const root = document.documentElement
     for (const [k, v] of Object.entries(FROZEN)) root.style.setProperty(k, v)
   })
   ```

   If you use live theming, this replaces `setNebColorPalette()` — don't call
   both.

This pins the raw scales exactly. The §2b/§2c semantic remaps are separate — add
those `:root` overrides too for a full pixel-match.

## Reference — default `#7c4ddb` palette, old → new

Light end is close; the dark half moved the most. Step `25` is new — it was
added later (for `--neb-bg-page` and `--neb-bg-{intent}-subtle`) and has no old
equivalent.

| --- | --- | --- | --- | --- |
| 25  | —         | `#FAF9FF` | —         | `#FCFBFE` |
| 50  | `#F8F6FD` | `#F5F3FF` | `#F8F8F8` | `#F7F6F9` |
| 100 | `#F2EDFB` | `#ECE8FF` | `#F1F0F2` | `#EEEEF1` |
| 200 | `#DED3F6` | `#DCD4FF` | `#DCDBDD` | `#DEDDE2` |
| 300 | `#CBB8F1` | `#C0AEFF` | `#C6C5C9` | `#BEBDC2` |
| 400 | `#A382E6` | `#A689FA` | `#9C99A1` | `#949398` |
| 500 | `#7C4DDB` | `#8C6BE0` | `#716D78` | `#76757A` |
| 600 | `#7045C5` | `#7C5BCC` | `#66626C` | `#67676C` |
| 700 | `#4A2E83` | `#6C4DB4` | `#444148` | `#535257` |

contrast table for any brand colour.
