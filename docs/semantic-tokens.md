# Semantic tokens

This document explains the semantic token layer in
[`assets/semantic.css`](../assets/semantic.css): how the tokens are named, why,
and how a component consumes them.

## The one rule

> **The prefix is the CSS property the token goes in.**

| Prefix | Property | Example |
| --- | --- | --- |
| `--neb-bg-*` | `background` | `background: var(--neb-bg-raised)` |
| `--neb-text-*` | `color` | `color: var(--neb-text-muted)` |
| `--neb-border-*` | `border` / `border-color` | `border: 1px solid var(--neb-border-subtle)` |
| `--neb-font-*` | `font` (pair with a `--neb-text-*` colour) | `font: var(--neb-font-label)` |
| `--neb-shadow-*` | `box-shadow` | `box-shadow: var(--neb-shadow-md)` |
| `--neb-ring-*` | `box-shadow` (focus rings) | `box-shadow: var(--neb-ring-primary)` |

Within a prefix, the **bare token is the neutral default** and an **intent
segment** opts into a hue:

```css
color: var(--neb-text); /* default body text */
color: var(--neb-text-muted); /* de-emphasised, still neutral */
color: var(--neb-text-error); /* error intent */

background: var(--neb-bg); /* default surface */
background: var(--neb-bg-hover); /* neutral hover state */
background: var(--neb-bg-primary-solid); /* saturated brand fill */
```

So to style something you ask two questions — *which property?* (→ prefix) and
*neutral, or which intent?* (→ segment). There is nothing else to learn.

## The three layers

| Layer | Where | Example | Role |
| --- | --- | --- | --- |
| **Primitives** | [`assets/tokens.css`](../assets/tokens.css) | `--space-4`, `--text-sm`, `--shadow-md`, `--font-semibold` | Raw, context-free scales. |
| **Color scales** | generated by [`modules/color.ts`](../modules/color.ts) | `--primary-color-500`, `--neutral-color-200` | Shade ramps from the six configured brand colors + a derived neutral ramp. |
| **Semantic tokens** | [`assets/semantic.css`](../assets/semantic.css) | `--neb-bg-raised`, `--neb-text-error`, `--neb-font-label` | Role-based. Names a *job*, resolves per-theme. |

**Components read only the semantic layer.** If a value you need has no semantic
token, add one — don't reach past to a scale (the always-dark image viewer and a
couple of `@keyframes` are the documented exceptions).

## Why a semantic layer exists

### Dark mode with no per-component work

Every semantic token resolves to a different primitive under `.dark-mode`:

```css
:root {
  --neb-bg-raised: var(--white);
}
.dark-mode {
  --neb-bg-raised: var(--neutral-color-900);
}
```

A component that writes `background: var(--neb-bg-raised)` is correct in both
themes with **no `.dark-mode` block of its own**. There are zero `.dark-mode`
blocks in `components/` — dark mode is entirely a re-resolution of these tokens.

### One place to retune, names that carry intent

Contrast, hover deltas, border strength, elevation on dark — tuned once here.
And `--neb-text-muted` tells a reviewer "deliberately de-emphasised" where
`--neutral-color-600` told them nothing.

## How resolution works (`:root` vs `.dark-mode`)

`:root` and `.dark-mode` are both single-class specificity, so:

- **`.dark-mode` on `<html>`** — the `.dark-mode` block wins by source order (it
  is second in the file).
- **`.dark-mode` on a descendant** — the token is re-declared on that subtree and
  inherited down.

Every token here points **straight at a color scale or primitive** — no token is
`var(--neb-…)` of another token. So each is just declared twice, once per block,
with a different value, and there is no aliasing subtlety to get wrong. (If you
ever add a token whose value *is* another `--neb-*` token, it must be re-declared
in `.dark-mode` — a custom property is substituted where it is declared, so a
light-only alias would leak its frozen light value into a nested dark subtree.)

## Token groups

### Backgrounds — `--neb-bg-*`

**Neutral** — an elevation/interaction stack:

| Token | Job |
| --- | --- |
| `--neb-bg-page` | The page/body background — bottom of the stack. |
| `--neb-bg` | Default component background (cards, inputs, panels). |
| `--neb-bg-raised` | Lifted above the page — menus, popovers, sticky headers. Light: same as `page`, separated by shadow. Dark: a step *lighter*. |
| `--neb-bg-subtle` | The faintest neutral fill — table headers, inset wells, code blocks. The neutral counterpart of `--neb-bg-{intent}-subtle`. |
| `--neb-bg-muted` | One step more — a quiet filled area. |
| `--neb-bg-hover` / `--neb-bg-active` | Interaction states for otherwise-transparent rows / list items / ghost buttons. `active` is one step stronger. |
| `--neb-bg-selected` | Persistent "this row is selected" fill — tinted with the **primary** hue, so selection reads as a brand action. |
| `--neb-bg-disabled` | Fill for disabled controls. |
| `--neb-bg-backdrop` | The dimming layer behind a modal or drawer — `rgba()` over a neutral triple. |
| `--neb-bg-neutral-solid` (+ `-hover`, `-disabled`) | Saturated grey fill — a neutral/secondary button. |

**Intent** (`primary`, `success`, `error`, `warning`, `info`) — the same six rungs each:

| Rung | Job |
| --- | --- |
| `--neb-bg-{intent}` | Tinted fill for a badge / alert body. |
| `--neb-bg-{intent}-subtle` | The lightest tint — large fill areas, row highlight. Same shade level as neutral `--neb-bg-subtle`. |
| `--neb-bg-{intent}-hover` | Hover state for a `-{intent}` / `-subtle` element. |
| `--neb-bg-{intent}-solid` | Saturated, full-strength fill — a primary button at rest. |
| `--neb-bg-{intent}-solid-hover` | Hover for `-solid`. |
| `--neb-bg-{intent}-solid-disabled` | Disabled state for a `-solid` element. |

Pair every `-solid` fill with `color: var(--neb-text-on-solid)`.

The neutral and intent background sets don't have identical shapes, on purpose:
neutral backgrounds carry an **elevation** story (`page` → `raised` → `subtle`)
that a red alert box simply doesn't have, so neutral names its levels by
structural role while intent names them by tint strength. The levels that *do*
correspond: `--neb-bg-subtle` ↔ `--neb-bg-{intent}-subtle`, `--neb-bg-muted` ↔
`--neb-bg-{intent}`, `--neb-bg-hover` ↔ `--neb-bg-{intent}-hover`,
`--neb-bg-neutral-solid` ↔ `--neb-bg-{intent}-solid`.

### Text — `--neb-text-*`

**Neutral** — an emphasis ladder:

| Token | Job |
| --- | --- |
| `--neb-text` | Body text, headings, labels — the default. |
| `--neb-text-muted` | De-emphasised — secondary copy, help text, table cells, standalone icons. |
| `--neb-text-subtle` | Barely-there — placeholders, timestamps, captions. |
| `--neb-text-disabled` | Text/icons in disabled controls. |
| `--neb-text-on-solid` | Text/icons on a saturated `--neb-bg-*-solid` fill. White in both themes. |

**Intent** — one token per hue, plus a hover:

| Token | Job |
| --- | --- |
| `--neb-text-{intent}` | Intent-coloured text and icons — an error message, a success tick, a "Retry" affordance, the required-field star. |
| `--neb-text-{intent}-hover` | Hover state for the above. |

`--neb-text-{intent}` doubles as the colour for **thin accent lines that should
read as the intent** — a checked checkbox/radio border, an active-tab underline,
a drag-target outline. Colouring a 1–2px indicator is the same visual decision
as colouring text, and (unlike a `--neb-border-*` token) it stays visible in
dark mode. Use a `--neb-border-*` token for actual box borders.

### Borders — `--neb-border-*`

**Neutral**:

| Token | Job |
| --- | --- |
| `--neb-border-subtle` | Hairline dividers, table row lines — the default, most-used. |
| `--neb-border` | A normal visible control border (input at rest). |
| `--neb-border-strong` | Emphasised — hover on an input, a deliberately boxed region. |
| `--neb-border-disabled` | Disabled controls. |
| `--neb-border-focus` | A control while focused — pair with `box-shadow: var(--neb-ring-primary)`. |
| `--neb-border-error` | A field in an error state — pair with `var(--neb-ring-error)`. |

**Intent**:

| Token | Job |
| --- | --- |
| `--neb-border-{intent}` | Border matching a `--neb-bg-{intent}` fill (badge, alert). |
| `--neb-border-{intent}-strong` | Emphasised version. |
| `--neb-border-{intent}-alert` | A full `border` shorthand (width + style + colour) for an alert's accent stripe — `2px` light, `1px` dark. Consumed as `border: var(…)`, so the rule still holds. |

### Focus rings — `--neb-ring-*`

`--neb-ring-primary`, `--neb-ring-error`, `--neb-ring-neutral`. Each is a
**`box-shadow` value** (a 4px spread ring + a 1px drop), not a colour — drop it
into `box-shadow` on `:focus-visible`. Resolves light/dark automatically. Pair
with the matching `--neb-border-focus` / `--neb-border-error`.

### Elevation — `--neb-shadow-*`

`xs → sm → md → lg → xl → 2xl → 3xl`, a monotonic depth ramp. Dark mode keeps the
geometry but raises alpha and builds on pure black (the light shadows are built
on `neutral-900` and vanish against a `neutral-950` page). Choose by float
distance: `sm` for a card, `md` for a dropdown, `lg`+ for a modal.

### Typography — `--neb-font-*`

A `--neb-font-*` token is only the `font` shorthand — it carries no colour. Pick
the colour from the text ladder alongside it:

```css
.label {
  font: var(--neb-font-label);
  color: var(--neb-text);
}
.hint {
  font: var(--neb-font-hint);
  color: var(--neb-text-muted);
}
```

| Role | Use | Weight / size / leading | Usual colour |
| --- | --- | --- | --- |
| `--neb-font-title-lg` | Page title | semibold / 30px / tight | `--neb-text` |
| `--neb-font-title` | Section title | semibold / 18px / normal | `--neb-text` |
| `--neb-font-heading` | Sub-heading, card header | semibold / 16px / normal | `--neb-text` |
| `--neb-font-body` | Paragraph copy | regular / 16px / relaxed | `--neb-text-muted` |
| `--neb-font-body-sm` | Dense copy, table cells | regular / 14px / normal | `--neb-text-muted` |
| `--neb-font-label` | Form labels, control text | medium / 14px / normal | `--neb-text` |
| `--neb-font-label-strong` | Emphasised label | semibold / 14px / normal | `--neb-text` |
| `--neb-font-hint` | Field help text | regular / 12px / normal | `--neb-text-muted` |
| `--neb-font-caption` | Smallest — metadata, overline | medium / 12px / normal | `--neb-text-subtle` |

The "usual colour" column is guidance, not a rule — use `--neb-text-error` on a
hint under an invalid field, and so on. Notes on the `font` shorthand:

- It **resets** `font-style`, `font-variant`, `font-stretch` to `initial` by
  design — set those explicitly afterwards if needed.
- `--neb-font-family` must stay **last** in the value. Override the family
  app-side by redefining `--neb-font-family`.

## Adding or changing a token

1. **Declare it in both `:root` and `.dark-mode`.** A token in only one block is a
   silent bug in the other theme.
2. **If the value is `var(--neb-…)` (an alias), re-declare it in `.dark-mode`**
   even if the text is identical (see [resolution](#how-resolution-works-root-vs-dark-mode)).
3. **Point at a scale or primitive, never a hardcoded hex** (`--white` / `--black`
   are the only raw values, used where a fixed colour is intentional).
4. **Keep the intent grid uniform** — a new `--neb-bg-{intent}` rung is added to
   all five chromatic intents.
5. Run `pnpm lint --fix` (ESLint formats CSS here — no Prettier).

## Quick reference

| I'm styling… | Token |
| --- | --- |
| the box behind my component | `--neb-bg` |
| a menu / popover / floating panel | `--neb-bg-raised` + `--neb-shadow-md` |
| a hover state on a list row | `--neb-bg-hover` |
| a selected row | `--neb-bg-selected` |
| a divider line | `--neb-border-subtle` |
| an input border at rest | `--neb-border` |
| a heading / label | `--neb-font-heading` (or `-label`) + `--neb-text` |
| paragraph copy | `--neb-font-body` + `--neb-text-muted` |
| secondary / helper text | `--neb-text-muted` |
| a placeholder | `--neb-text-subtle` |
| a standalone icon | `--neb-text-muted` |
| a faint inset area (table header, well) | `--neb-bg-subtle` |
| a primary button | `--neb-bg-primary-solid` + `--neb-text-on-solid` + `--neb-bg-primary-solid-hover` |
| a subtle success alert | `--neb-bg-success-subtle` + `--neb-border-success` + `--neb-text-success` |
| an inline "Retry" / error link | `--neb-text-error` / `--neb-text-error-hover` |
| a checked checkbox / active-tab indicator | `--neb-text-primary` (thin accent line) |
| a focused input | `--neb-border-focus` + `box-shadow: var(--neb-ring-primary)` |
| an invalid input | `--neb-border-error` + `box-shadow: var(--neb-ring-error)` |
